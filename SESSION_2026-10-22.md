## Provisioning conventions that must be kept
1. EL8 + Kubernetes stream `v1.29`.
2. Runtime is `containerd` with CRI enabled and `SystemdCgroup=true`.
3. Worker join uses file-based method:
   - `/vagrant/kubeadm-join-command.sh`
4. Worker scripts sanitize CRLF when executing join command (`tr -d '\r'`) to avoid kubeadm argument errors on Windows-authored files.
5. VMware shared folder config avoids unsupported `dmode/fmode` options.

## Cert renewal model
- Control plane cert checks/renew logic is in `k8s-cert-renew.sh`.
- Renewal of standard control-plane certs does **not** require worker rejoin.
- Worker rejoin is only needed after CA replacement or full control-plane reset.

## Quick recovery checklist (next time)
1. Start control plane VM and verify API server is healthy.
2. Regenerate join command from control plane if needed.
3. Ensure each worker folder contains `kubeadm-join-command.sh`.
4. Provision workers.
5. Verify all nodes are `Ready` from control plane.

## Known pitfalls encountered and fixed
- VMware suspended/stale VM metadata (`vmrun canceled`) requiring destroy + metadata cleanup.
- EL8 module conflicts (`containerd.io` vs `runc`/container-tools`) resolved by module reset and package order.
- CRLF in join script causing `kubeadm join` extra argument error.
